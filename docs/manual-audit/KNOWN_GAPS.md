# Известные пробелы и ограничения проверки

Ниже — только то, что видно из **текущего кода**, схемы и тестов. Это не журнал уже пройденных ручных багов: ручной аудит ещё не выполнялся.

---

## 1. Частично реализовано

### GAP-PAY-001 — Платёжный провайдер-заглушка

- Файл: `src/server/payments/provider.ts`.
- `stubPaymentProvider.createPaymentIntent` возвращает `checkoutUrl: null`, `message: "Оплата скоро появится"`.
- UI Аудитории (`PaymentCheckoutPanel`) всё равно открывает константу `TOCHKA_CHECKOUT_URL` и ставит заявку на ручную проверку директору.
- Сайт не получает подтверждение от банка. Рабочий путь оплаты в продукте сейчас: заявка ученика → «Подтвердить» в Доходах.
- Статус функции `AUD-PAY-002`: **частично реализовано**.

### GAP-PAY-002 — Технические URL оплаты

`/auditoria/pay/checkout` и `/auditoria/pay/complete` не в сайдбаре. Имеют смысл только внутри потока оплаты. Без реального провайдера complete не означает «деньги пришли».

## 4. Ожидаемые ограничения продукта (не баги сами по себе)

- Чат только в Кафедре и Аудитории.
- Middleware не проверяет роль, только сессию (локально при демо-входе даже сессию не требует).
- RoleSwitcher меняет URL, не роль.
- Расписание дирекции — сетка **одного** выбранного преподавателя, не всех сразу (текст на странице).
- Напоминания Прессы личные, не генерятся из учеников/пробных.
- Оценки занятий: одноразовые; только при `present` и прошедшем/`done`; нет экрана в Кафедре/Дирекции.
- Обратная связь: нет API ChatGPT, только копирование промпта.
- Школьная библиотека в bootstrap скрыта от не-директора.
- Пресса изолирована от payroll API.

## 5. Пробелы автотестов относительно UI

Автотесты в основном серверные (PGlite) и lib-хелперы. **Нет e2e/Playwright по кабинетам.** Поэтому даже блок «подтверждено тестами» требует ручного UI.

Слабее покрыты автотестами (статус «реализовано, требует ручной проверки»):

- Главная `/` и копирайт/ссылки кабинетов.
- Обзор дирекции (клиентские счётчики из store).
- Профили Кафедры и Аудитории (сохранение через upsert).
- Редактор тестов (UI `TestEditorDialog`) целиком.
- Фото преподавателя.
- Адаптив сайдбара.
- Закрытие диалога оценки 1–7 без сохранения (логика в компоненте, сервер не вызывается).
- Совпадение цифр Обзора дирекции с реальными списками.

Серверные тесты **существуют** для: auth/rbac, занятия, ДЗ, теория, knowledge, тарифы/очередь оплаты, payroll, press cabinet, reminders, monthly feedback, lesson ratings, chat, notes, seed safety.

Актуальное «все тесты зелёные» в этой инвентаризации **не прогонялось** как обязательный шаг: для статусов достаточно факта наличия тестов в `tests/`. Если нужно — отдельной командой `npm test` (PGlite, локальные данные PostgreSQL не трогает).

## 6. Спорные / уточнять при проходе

1. **Кнопка удаления ученика** — API `deleteStudent` есть; в списке основной путь — архив. Есть ли hard-delete в UI карточки, видно только при открытии.
2. **Превью payroll backfill** — action в platform есть; наличие кнопки в `salaries-workspace` нужно подтвердить глазами (`DIR-SAL-005`).
3. **Кафедра создаёт учеников** — `editable` true для `kafedra`; серверные ограничения upsertStudent (может ли учитель создавать или только директор) проверяются уровнем D.
4. **Демо vs school seed:** локальный сид — `org_school_qa`; отдельный demo-org может существовать в базе. Dev-переключатель показывает accounts из `features.demoAccounts`. Смотрите, что открылась нужная школа.
5. **Идемпотентность** платёжных и completeLesson действий завязана на заголовок ключа из клиента — повторный клик в UI должен быть безопасен, но это надо увидеть.

## 8. Опасные действия (не выполнять «за компанию»)

Не делайте в существующей базе без явного решения:

- «В архив» / hard-delete ученика или преподавателя.
- «Удалить» занятие или серию, особенно прошедшие.
- Смена тарифа и «Подтвердить» / «Отклонить» оплату.
- Выплата зарплаты, смена ставок слотов.
- «Отключить» пользователя.
- «Отключить серию» напоминаний (если серия нужна).
- Массовый `transferKnowledge`.
- `npm run start:local` **без** keep (пересидирует `org_school_qa`).
- `db:seed`, `db:seed:school`, любые destructive SQL.

Для безопасного знакомства с UI используйте пункты, помеченные **Чтение**.
