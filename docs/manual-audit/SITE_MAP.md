# Карта сайта

Источник: `src/app/**/page.tsx`, `src/lib/cabinet-nav.ts`, `src/middleware.ts`, `src/lib/auth/roles.ts`, `src/components/layout/*`.

Всего обнаружено **61 уникальный файловый маршрут** (`page.tsx`). Из них **4 — редиректы** без собственной страницы, **5 — публичные**, остальные — кабинеты.

Часовой пояс интерфейса и расчётов дат: `Europe/Moscow`.

## 1. Роли и доступ

| Роль | Кабинет | Домашний URL | Навигация |
|---|---|---|---|
| `director` | Дирекция | `/direkciya` | 10 пунктов |
| `teacher` | Кафедра | `/kafedra` | 9 пунктов |
| `student` | Аудитория | `/auditoria` | 6 пунктов |
| `press` | Пресса | `/pressa` | 8 пунктов |

**Ограничение middleware** (`src/middleware.ts`): для `/direkciya`, `/kafedra`, `/auditoria`, `/pressa` нужна cookie сессии, **кроме** режима демо-входа (`isDemoLoginAllowed()`, локально включён). Роль в middleware **не проверяется**.

**Ограничение страниц:** большинство страниц кабинетов не делают серверный 403 по роли. Данные приходят из `/api/bootstrap` уже отфильтрованными. Мутации идут через API и проверяют роль на сервере (`requireAuth` + `requirePress` / `requireTeacherProfile` / `requireStudentProfile` / роль директора в сервисах).

**Страницы, доступные всем авторизованным (по URL):** любой залогиненный пользователь технически может открыть чужой префикс кабинета через переключатель ролей в сайдбаре. Ожидание: UI может быть пустым или частично рабочим; запись чужих данных должна отклоняться API.

**Страницы только для роли (по смыслу продукта и API):**

- Дирекция: управление учениками/преподавателями, зарплаты, тарифы, доходы, доступ, база знаний школы, расписание выбранного преподавателя, результаты.
- Кафедра: сегодня, свои ученики, своё расписание, темы, теория, тесты, оценки, обратная связь, профиль преподавателя. Чат.
- Аудитория: главная, ДЗ, теория, история занятий (оценки), оплата, профиль. Чат.
- Пресса: напоминания, обратная связь, отметки учеников, CRM учеников, преподаватели (расписание для пробных), пробные уроки, аналитика.

**Общие виджеты всех кабинетов:** личные заметки (`NotesWidget`). Чат (`ChatWidget`) только в Кафедре и Аудитории.

**Имперсонация:** директор может «войти» в кабинет преподавателя/ученика/прессы (`EnterCabinetButton` → `/api/admin/impersonate`). Баннер «Вы просматриваете кабинет пользователя от имени администратора».

## 2. Публичные страницы

### `/` — Главная «Неодин»

- **Роли:** все (без сессии).
- **Назначение:** выбор кабинета и ссылки на вход/регистрацию.
- **Разделы:** заголовок «Выберите кабинет», ссылки на четыре кабинета, «Войти», «Регистрация преподавателя», «Регистрация ученика».
- **Действия:** переход по ссылкам.
- **Сущности:** нет.
- **API:** нет.
- **Доступ:** без ограничений.

### `/login` — Вход

- **Роли:** гости; авторизованный перенаправляется в свой кабинет.
- **Назначение:** вход по email/паролю.
- **Действия:** отправка формы, переход на регистрацию, при `needsBootstrap` — редирект на `/setup`.
- **API:** `GET /api/auth/features`, `GET /api/auth/me`, `POST /api/auth/login`, CSRF.
- **Сущности:** `users`, `sessions`, `login_attempts`.

### `/setup` — Первичная настройка администратора

- **Роли:** только пока `features.needsBootstrap === true`; иначе редирект на `/login`.
- **Назначение:** создать первую организацию и директора.
- **Действия:** форма (токен, ФИО, email, пароль, название организации).
- **API:** `GET /api/auth/features`, `POST /api/auth/bootstrap-admin`.
- **Сущности:** `organizations`, `users`, `memberships`.
- **Готовность:** реализовано; на уже сидированной локальной базе страница обычно недоступна (bootstrap не нужен).

### `/register/teacher` — Регистрация преподавателя

- **Роли:** гости.
- **Назначение:** публичная регистрация преподавателя.
- **API:** `POST /api/auth/register/teacher`.
- **Сущности:** `users`, `memberships`, `teachers`.
- **Изменяет данные:** да. Не выполнять без разрешения, если не нужна новая учётка.

### `/register/student` — Регистрация ученика

- **Роли:** гости.
- **Назначение:** публичная регистрация ученика.
- **API:** `POST /api/auth/register/student`.
- **Сущности:** `users`, `memberships`, `students`.
- **Изменяет данные:** да.

## 3. Дирекция (`/direkciya`)

Навигация (`direkciyaNavItems`): Обзор, Ученики, Преподаватели, Зарплаты, База знаний, Тарифы, Доходы, Доступ, Расписание, Результаты.

### `/direkciya` — Обзор

- **Название в UI:** «Обзор дирекции».
- **Роль:** director (по продукту).
- **Назначение:** сводка сети и домашки, требующие внимания.
- **Разделы:** «Требует внимания» (к проверке / просрочено), счётчики преподавателей/учеников/занятий, ссылка «К результатам →».
- **Действия:** просмотр, переход.
- **Сущности:** students, teachers, lessons, homework assignments (через bootstrap).
- **API:** bootstrap (чтение).

### `/direkciya/students` — Ученики

- **UI:** «Ученики», вкладки «Ученики в работе» / «Ученики в архиве».
- **Действия:** поиск, фильтр преподавателя («Все преподаватели» / «Без преподавателя» / конкретный), фильтр статуса, «Добавить ученика», открытие карточки, «В архив», «Вернуть в работу», назначение тарифа из списка.
- **Сущности:** `students`, `users`/`memberships`, `student_tariff_assignments`, `teachers`.
- **API:** `POST /api/platform` (`upsertStudent`, `archiveStudent`, `restoreStudent`, `assignTariff`, `setStudentPurchaseTariff`).

### `/direkciya/students/[id]` — Карточка ученика

- **Назначение:** детальный просмотр/редактирование того же набора полей, что и диалог списка (ФИО, класс, телефон, преподаватель, статус, тариф, контакты родителей, заметки).
- **Связанные страницы:** та же логика `StudentsByTeacher` / student detail.

### `/direkciya/teachers` — Преподаватели

- **UI:** «Добавить преподавателя», таблица, статусы.
- **Действия:** создать/редактировать (ФИО, предметы, специализации, телефон, email, био, дата начала, статус, цены, ставки слотов 1–5, длительность, рабочие дни, заметки, фото), «Сохранить», «Удалить», «Войти в кабинет» (имперсонация).
- **API:** `upsertTeacher`, `deleteTeacher`, `setTeacherPayRates`, `POST /api/admin/teachers/[id]/photo`, impersonate.

### `/direkciya/teachers/[id]` — Карточка преподавателя

- Детальная карточка / редактирование того же преподавателя.

### `/direkciya/salaries` — Зарплаты

- **Назначение:** обзор начислений, долг, выплаты, ставки, детализация преподавателя.
- **Действия:** выбор периода, раскрытие преподавателя, создание выплаты, просмотр истории, превью backfill (если есть в UI).
- **API:** `getPayrollOverview`, `getTeacherPayrollDetail`, `createTeacherPayout`, `previewPayrollBackfill`, `getTeacherPayRates`, `setTeacherPayRates`.
- **Сущности:** `teacher_pay_rates`, `teacher_payroll_slots`, `teacher_payroll_entries`.
- **Опасно:** выплаты и смена ставок.

### `/direkciya/knowledge` — База знаний

- **Назначение:** школьная библиотека и материалы преподавателей; перенос в школу.
- **Действия:** фильтры вида (теория / тест / тема), блоки «школа» / «преподаватели», создание теории, перенос (`transferKnowledge`), сохранение в школьную библиотеку (`saveToSchoolLibrary`).
- **Вложенные:** `/direkciya/knowledge/theory/new`, `/direkciya/knowledge/theory/[id]`.

### `/direkciya/tariffs` — Тарифы

- **Действия:** список, создание/редактирование (название, цена, дни, лимит занятий, частота, состав, статус), архивация тарифа.
- **API:** `upsertTariff`, `archiveTariff`.
- **Опасно:** архивация и правка действующих тарифов.

### `/direkciya/payments` — Доходы

- **UI:** «Доходы», фильтры статусов платежей, «Подтвердить» / «Отклонить» для заявок «На проверке».
- **API:** `getIncomeOverview`, `adminMarkPaymentPaid`, `adminRejectPayment`.
- **Опасно:** подтверждение и отклонение оплаты.

### `/direkciya/users` — Доступ (Пользователи)

- **UI:** «Пользователи», форма «Новый аккаунт», таблица, «Создать», «Отключить» / «Включить», «Войти в кабинет».
- **Клиентская защита:** не-директор видит «Управление пользователями доступно только дирекции.»
- **API:** `GET/POST /api/admin/users`, `PATCH /api/admin/users/[id]`, impersonate.
- **Опасно:** отключение учёток, создание новых ролей.

### `/direkciya/schedule` — Расписание

- **UI:** «Расписание», выбор преподавателя, недельная сетка.
- **Действия:** слот → диалог занятия, серия, удаление, превью пробного.
- **API:** `upsertLesson`, `createRecurringSchedule`, `deleteLesson`.
- **Опасно:** удаление занятий и серий.

### `/direkciya/results` — Результаты

- **Назначение:** назначения тестов/ДЗ выбранного преподавателя, фильтры, проверка.
- **API:** bootstrap + `reviewHomeworkAssignment` / `/api/assignments/[id]/review`.

## 4. Кафедра (`/kafedra`)

Навигация: Сегодня, Ученики, Расписание, Темы, Теория, Тесты, Оценки, Обратная связь, Мой профиль.

Чат в оболочке кабинета.

### `/kafedra` — Сегодня

- **Назначение:** занятия на сегодня (Москва), просроченные неотмеченные, пробные на сегодня.
- **Действия:** отметить посещаемость, завершить занятие (`CompleteLessonDialog`), редактировать занятие, содержание урока, превью пробного.
- **API:** `setAttendance`, `completeLesson`, `upsertLesson`, `setLessonTopics`.
- **Сущности:** `lessons`, `attendances`, `lesson_topics`, `trial_lessons`, ledger тарифа, payroll slots.

### `/kafedra/students` и `/kafedra/students/[id]`

- Список **своих** учеников (без вкладок архива дирекции). Создание — если `editable` для преподавателя включено в компоненте (директорский режим полного CRUD; преподаватель видит своих).
- Нужно при ручной проверке убедиться, какие кнопки реально видны преподавателю (см. реестр `KAF-STU-*`).

### `/kafedra/schedule` — Расписание

- Своя недельная сетка, создание по клику на слот, серии, пробные.

### `/kafedra/topics` и `/kafedra/topics/[id]` — Темы

- Разделы тем, создание/перемещение/удаление тем, привязка к занятиям.

### `/kafedra/theory`, `/kafedra/theory/new`, `/kafedra/theory/[id]`, `/kafedra/theory/[id]/results`

- Список теории, редактор, назначение ученикам, результаты просмотра.
- **API:** `upsertTheory`, `deleteTheory`, `assignTheory`, файлы `/api/theory/...`.

### `/kafedra/tests` — Тесты

- Шаблоны тестов (черновик / опубликован / архив), редактор, архивация/восстановление.
- **API:** `upsertHomework`, `deleteHomework`, `restoreHomework`, `publishHomework`, `assignHomework`.

### `/kafedra/grades` — Оценки

- Вкладки учеников и статистики тестов, проверка работ.
- **API:** `getTestGradesStats`, review assignment.

### `/kafedra/feedback` — Обратная связь

- Список учеников преподавателя за календарный месяц, прогресс черновиков/отправки, переключатель месяца.
- **API:** `GET /api/feedback?action=teacherList`.

### `/kafedra/feedback/[studentId]` — Карточка обратной связи

- Черновик, автосохранение, «Сохранить черновик», «Отправить в Прессу», снимок метрик.
- **API:** `teacherReport`, `saveDraft`, `submit`.

### `/kafedra/profile` — Мой профиль

- Профиль преподавателя (`TeacherProfilePanel`): просмотр/правка своих полей (в рамках того, что панель реально сохраняет).

### `/kafedra/results` — скрытый редирект

- **Не в навигации.** `redirect("/kafedra/grades")`.

## 6. Пресса (`/pressa`)

Навигация: Обзор, Напоминания, Обратная связь, Отметки учеников, Ученики, Преподаватели, Пробные уроки, Аналитика.

Чата нет. Заметки есть.

API кабинета: `GET/POST /api/press`, плюс `/api/feedback`, `/api/lesson-ratings`.

### `/pressa` — Обзор

- **UI:** «Пресса», дата «· Рабочий день», блок **«Напоминания на сегодня»** (тот же `PressRemindersWorkspace` с `embeddedToday`), кнопка «Добавить напоминание», прогресс дня.

### `/pressa/reminders` — Напоминания

- Виды: Сегодня / Предстоящие / Выполненные / Все; фильтры разовые/регулярные и статуса; даты для «Все»/«Выполненные».
- Действия: создать, править, выполнить, снять отметку, отключить серию, архивировать.

### `/pressa/feedback` — Обратная связь

- Отчёты преподавателей за месяц, фильтр статуса (по умолчанию «ожидают»).
- Карточка: `/pressa/feedback/[id]`.

### `/pressa/feedback/[id]` — Карточка отчёта

- Комментарий преподавателя (только чтение), снимок метрик, «Скопировать промпт для ChatGPT», «Взять в работу», «Отметить обработанным», «Итоговый текст для родителя», «Сохранить текст», чекбокс «Сообщение родителю отправлено».

### `/pressa/ratings` — Отметки учеников

- Период, преподаватель, кнопка «Требуют внимания», средний рейтинг, лента по дням, подгрузка.

### `/pressa/students` и `/pressa/students/[id]`

- CRM: поиск, корзины new/active/archived, карточка: актуальная информация, журнал взаимодействий. **Нет UI «следующий контакт»** (сервис задач контакта остался в БД без экрана).

### `/pressa/teachers` и `/pressa/teachers/[id]`

- Список преподавателей для выбора слота пробного; карточка расписания преподавателя (`PressTeacherSchedule`).

### `/pressa/trials` и `/pressa/trials/[id]`

- Список пробных (колонки с именем), создание/правка/отмена, заметки взаимодействия, события.

### `/pressa/analytics` — Аналитика

- Период from/to, фильтр преподавателя и владельца (сотрудника Прессы), метрики пробных и воронки.

## 7. Сводка маршрутов

### В навигации (33 пункта сайдбара)

Дирекция 10 + Кафедра 9 + Аудитория 6 + Пресса 8.

### Есть страница, нет пункта навигации

- Карточки: `.../students/[id]`, `.../teachers/[id]`, `.../topics/[id]`, теория `[id]`/`new`/`results`, ДЗ `[id]`, история `[id]`, feedback `[id]`/`[studentId]`, trials `[id]`.
- Оплата: `/auditoria/pay/checkout`, `/auditoria/pay/complete`.
- Публичные: `/`, `/login`, `/setup`, `/register/*`.

### Существуют в коде, но только редирект

- `/kafedra/results` → `/kafedra/grades`
- `/auditoria/results` → `/auditoria/homework`
- `/auditoria/schedule` → `/auditoria`
- `/auditoria/learning` → `/auditoria/history`

Их достаточно открыть один раз (блок технических маршрутов в чек-листе). Полноценной реализации нет.

### Страницы без полноценной реализации / с заглушкой

- Поток оплаты ученика: UI и заявка на ручную проверку есть; провайдер `stubPaymentProvider` возвращает «Оплата скоро появится» и не подтверждает платёж автоматически.
- `/setup` на сидированной базе недоступен (не ошибка — bootstrap уже не нужен).
- Сервис `press_notifications` + `student_contact_tasks`: таблиц и кода нет в UI кабинета.
